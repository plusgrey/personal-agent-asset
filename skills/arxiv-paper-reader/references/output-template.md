# 输出模板

按下面的结构组织 `notes.md`。没有实质内容的小节可以删掉（比如纯实证论文可能没有"数学推导"），但**一级结构的顺序不要改**。

````markdown
# <论文标题>

> **arXiv**: [<id>](https://arxiv.org/abs/<id>) · **作者**: <作者> · **发表**: <日期 / 会议>
> **一句话总结**: <用一句话说清楚：针对什么问题，用什么方法，取得了什么效果>

## TL;DR

- **问题**: ...
- **洞察**: ...
- **方法**: ...
- **结果**: ...
- **启发**: ...

---

## 1. 出发点：为什么要做这件事

### 1.1 问题背景
这个问题是什么、为什么重要、在更大的图景里处于什么位置。

### 1.2 现有方法及其不足
| 方法 / 流派 | 核心思路 | 具体缺陷 |
| --- | --- | --- |
| ... | ... | ... |

### 1.3 本文的切入点
作者看到了什么关键观察或洞察？为什么沿着这个方向能解决上面的缺陷？
这是全文最重要的一节，要讲出"为什么是这个方向"。

## 2. 方法

### 2.1 整体框架
先给出全貌：流程、各模块、数据流。必要时用 mermaid 或 ASCII 画图。

### 2.2 关键设计
每个设计单独写成一小节：
- **做了什么**
- **为什么这么做**：对应 1.2 中的哪个缺陷
- **有什么替代方案，为什么没选**（如果论文讨论过或者能推断出来）

### 2.3 训练 / 推理细节
目标函数、算法伪代码、关键超参数。

## 3. 数学推导

（按 math-derivation.md 规范来写。每个推导是一个小节，二级结论第一次用到时插入。）

### 3.1 <推导目标，例如：从对数似然到 ELBO>
**目标**: 要证明或推出什么。
**前提与记号**: ...

推导步骤 ...

> **二级结论：<名称>**
> ...

**小结**: 这个推导说明了什么，它在方法里起什么作用。

## 4. 实验与效果

### 4.1 实验设置
数据集、指标、基线、算力规模。

### 4.2 主要结果
关键数字（注明来自表/图几），和最强基线比较。

### 4.3 消融与分析
哪些组件真正有效？哪些结论有实验支撑，哪些没有？

### 4.4 局限
作者承认的局限 + 你发现的局限（比如评测不充分、基线不公平、算力门槛高）。

## 5. 对一般开源项目的启发

不局限于这篇论文的领域，提炼可以迁移的东西：
- **可复用的思想 / 技巧**: 比如"把难优化的目标改写成逐步去噪的回归目标"
- **工程实践**: 哪些实现细节值得借鉴（参数化方式、训练稳定性技巧、评测方法）
- **落地建议**: 想在自己的项目里用，从哪里开始、要注意哪些坑、需要多少成本
- **相关开源实现**: 官方代码 / 主流复现（确认存在才写）

## 6. 关键问题自测

列出 3–5 个问题，检验自己是否真正读懂了，附简短答案。

## 附录：符号表

| 符号 | 含义 |
| --- | --- |
| ... | ... |
````
